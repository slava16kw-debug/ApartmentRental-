# Rental Apart KW

Одностраничное приложение на русском языке для учёта двух сдаваемых квартир и собственного жилья. Исходный код первой рабочей версии.

Светлая тема с боковой навигацией, карточками финансовых показателей и оранжевыми акцентами. Визуальные настройки собраны в `src/theme.css`; годовая таблица и все операции сохраняют привычную структуру.

## Что работает

- Главный экран в виде привычного годового листа: три квартиры рядом, месяцы по строкам, голубой/жёлтый/зелёный цвета из исходного Excel, годовые итоги и сроки поверки. Ниже — таблица расхода ресурсов; годы переключаются нижними вкладками. Нажатие на ячейку открывает нужную запись или ввод показаний на выбранную дату.
- Дашборд, фильтры по году, месяцу и квартире, финансовые графики и графики потребления.
- Вкладка «ЖКХ» после годового листа: редактируемый справочник квитанций и средних месячных сумм, сроки и примечания, отдельные красные/оранжевые/зелёные отметки по месяцам и сброс выбранного месяца в красный. Цвет можно менять сразу у всех активных квитанций, у выбранной квартиры или у произвольно отмеченных строк; скрытые квитанции не затрагиваются. Новый месяц начинается с красных отметок. Ориентиры и цветовые отметки не создают финансовых операций и не влияют на прибыль. Скрытые квитанции можно показать и вернуть в список; данные входят в JSON-копию и Excel.
- Договоры и история условий, начисления, частичная оплата, авансы, распределение платежа по месяцам, залоги отдельно от дохода.
- Показания воды, газа и электричества, проверка последовательности, замена прибора, сроки поверки.
- Расходы по квартирам, статус и фактическая дата оплаты, отдельный бюджет собственного жилья, возмещения и оценка по тарифам.
- Годовой результат по фактическим платежам, подробный состав показателей, план и прогноз отдельно.
- Годовая сводка показывает потенциал аренды при полной загрузке, полученную аренду, оплаченные расходы, итоговую прибыль и долю полученной аренды от потенциала. Наличные и переводы находятся под расходами по квартирам: нажатие на сумму открывает способы получения по платежам выбранного года и квартиры. Способы можно менять вместе или в отдельном платеже; суммы аренды и прибыль при этом сохраняются. Неуказанные способы и нераспределённая сверка года показаны отдельно.
- Проверяемый импорт исходного годового Excel и CSV, экспорт Excel/CSV, полная JSON-копия и восстановление.
- Серверное хранение в Cloudflare D1, защита от перезаписи при одновременном редактировании.

## Запуск и проверки

### Публикация на Vercel

`npm run build:vercel` собирает интерфейс в `vercel-dist`; `api/portfolio.js` обслуживает данные через закрытый Vercel Blob. Адреса, арендаторы и операции хранятся только в приватном объекте, а не в исходном коде или сборке. Обе опубликованные версии используют этот общий объект после миграции. Обновления защищены одновременно версией записи и атомарной проверкой ETag.

Включите Vercel Authentication (Standard Protection) и используйте защищённый адрес конкретного развёртывания. API принимает запросы только на системный `VERCEL_URL`, чтобы открытый пользовательский домен не раскрыл данные. На Vercel задаётся серверная переменная `BLOB_READ_WRITE_TOKEN`; такое же секретное значение задаётся в Sites. Исходная D1-база сохраняется как резервная копия. При первоначальном переносе записи временно блокируются переменной `RENTAL_DATA_MIGRATION_LOCK=true` до проверки копии, затем блокировка выключается значением `false`.

`scripts/blob-migration.mjs` принимает параметры только через stdin: проверяет приватное чтение/запись и конфликты ETag либо импортирует проверенную JSON-копию без перезаписи существующего объекта. Секреты и содержимое финансовых записей в журнал не выводятся. После публикации проверьте защищённый GET `/api/portfolio` и отказ доступа без входа.

Node.js 22.13+ (для тестов с `node:sqlite` рекомендуется Node.js 24).

```sh
npm ci
npm run build
npm test
```

Данные находятся в D1, в таблице `portfolio`: версия схемы и логические коллекции квартир, договоров, приборов и операций сохраняются одной транзакционной записью с оптимистической блокировкой. Для небольшого семейного портфеля это сохраняет целостность взаимосвязанных изменений. При дальнейшем расширении коллекции можно вынести в отдельные таблицы.

Изменения схемы: `npm run db:generate`. Миграции в `drizzle/` применяются хостингом при публикации; приложение не создаёт таблицы при обработке запросов.

`npm run build` создаёт Worker ES module в `dist/server/index.js` с включёнными ресурсами интерфейса. Публикация — через Sites по `.openai/hosting.json` с привязкой D1 `DB`.

## Приватность и конфигурация

Приложение размещается только в **owner-private Sites**. Платформа выполняет вход и защищает HTML и API. API использует одну общую семейную область данных внутри этой границы доступа. **Не публикуйте Worker напрямую в публичном доступе** без добавления серверной проверки аутентификации и членства.

Серверные переменные:

- `PRIVATE_SITE=true` — подтверждение конфигурации приватного хостинга; сама переменная не заменяет платформенную аутентификацию.
- `INITIAL_CONFIG` — необязательный серверный JSON с адресами и датами поверки. Настраивается приватно на хостинге, в Git не хранится. Применяется один раз при создании базы.

Репозиторий содержит только универсальные настройки трёх квартир и согласованные стартовые ставки 50 000 и 35 000 ₽. Адреса, арендаторы, операции и резервные копии в исходный код не включаются.

## Правила расчётов

Прибыль от аренды = полученная аренда + возмещения − оплаченные собственником расходы сдаваемых квартир. Учитываются фактические даты денег, до текущего дня включительно. Залоги, будущие операции и собственное жильё исключаются. Расходы собственного жилья показаны отдельно. Налог учитывается как введённый расход, автоматически не начисляется.

Если собственник подтвердил итог закрытого года, а месячная детализация требует сверки, он хранится в `settings.annualRentTotals`. Разница с суммой записей применяется только к общему итогу полного года. Она отдельно показана в годовом листе, отчёте, детализации показателя и Excel; без подтверждения месяцев и квартир разница на них не распределяется и платёж или расход не создаётся. После исправления детализации разница пересчитывается автоматически. Подтверждённый годовой итог не применяется к незавершённому году.

Под фактическим годовым итогом показан потенциал при полной загрузке за все 12 месяцев выбранного года. Для каждого месяца берётся последняя известная договорная ставка, действовавшая к концу месяца. На месяцы без договора переносится последняя известная ставка, а до первого договора — первая известная. Для архивных договоров без известных ставок используется сумма полученной аренды за соответствующий месяц. Нули и пропуски не задают новую ставку. Подтверждённые полные месячные ставки для частичных архивных платежей хранятся отдельно в `contract.potentialRates` и не создают начислений или задолженности. При отсутствии известной ставки показано «—». Потенциальная прибыль = потенциальная аренда + внесённые возмещения − уже оплаченные расходы сдаваемых квартир; будущие расходы не прогнозируются. Этот расчёт не создаёт поступлений или долгов.

Показания 1 февраля минус показания 1 января дают январский расход. Незаполненные значения не превращаются в ноль. Нестандартный или многомесячный интервал показан отдельно, без выдуманного распределения по месяцам.

Начало учёта по умолчанию — первый день текущего месяца. До переноса всей истории нельзя считать рассчитанную задолженность достоверной за прошлые периоды. Отсутствие денег в истории не устанавливает простой квартиры.

Нулевая арендная запись сохраняет факт отсутствия поступления за выбранный месяц: её можно создать, исправить и выгрузить, в том числе без договора для пустующей квартиры. При диапазоне месяцев ноль сохраняется для каждого месяца. Ноль не заменяет пустое поле, не увеличивает доход и не отменяет действующие договорные начисления: при выезде жильцов завершите договор. Расходы, возмещения и операции с залогом по-прежнему требуют положительной суммы.

Импорт старого Excel требует проверки. Денежные записи не выбраны по умолчанию. Если точный день получения неизвестен, сохраняется точность «только месяц»; в интерфейсе и Excel показывается месяц, а первое число хранится как техническая дата для расчётов. Кумулятивная аренда 2022 года автоматически не переносится. Архивные поступления не устанавливают договорные начисления: неизвестные обязательства отмечены отдельно, долги и авансы по ним не выдумываются. После ручного подтверждения начисления долг рассчитывается обычным образом. Полное восстановление приложения выполняется JSON-копией; Excel/CSV — аналитические выгрузки.

День оплаты у новых и исправленных договоров с `dueDayFromStart=true` автоматически берётся из даты начала договора. Дата первого платежа может быть указана отдельно. В годовом обзоре день оплаты выделен крупным жирным шрифтом.

Годовой план с учётом простоя считается отдельно функцией `occupiedRentPlan`: известные договорные начисления за 12 месяцев, включая частичные и ещё не оплаченные месяцы, плюс архивная аренда за периоды без восстановленных условий. Месяцы без договора и записей не добавляют аренду. Получение денег по известному договору не меняет план и не учитывается повторно. Процент выполнения = фактически полученная аренда за год / этот план; при нулевом плане показано «—». Прибыль по текущим расходам использует только уже внесённые возмещения и оплаченные расходы, будущие расходы не прогнозируются.

## Оформление

В верхней панели и настройках доступны три темы: белая, светлая и тёмная. По умолчанию используется тёмная тема; выбранная вручную тема сохраняется в localStorage этого браузера и применяется до отрисовки страницы. Переключение не отправляет финансовые данные на сервер и сохраняет незавершённый ввод. Цвета квартир и месячных отметок ЖКХ адаптируются к выбранной теме.

## Дальнейшее развитие

Внешние push/email-уведомления, автоматическое формирование регулярных расходов и применение залога в счёт долга пока не реализованы. Смена назначения квартиры с историей аренды заблокирована до добавления периодов использования, чтобы не искажать прошлые отчёты. Семейный доступ для второго пользователя настраивается отдельно на хостинге.

Проверки: финансовые сценарии, интервалы показаний, импорт/экспорт, API и конкурентные сохранения, а также интеграционные проверки форм в JSDOM. Проверка в настоящем браузере требует доступной инфраструктуры Sites preview.
