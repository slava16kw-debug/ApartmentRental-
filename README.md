# Мои квартиры

Одностраничное приложение на русском языке для учёта двух сдаваемых квартир и собственного жилья. Исходный код первой рабочей версии.

## Что работает

- Главный экран в виде привычного годового листа: три квартиры рядом, месяцы по строкам, голубой/жёлтый/зелёный цвета из исходного Excel, годовые итоги и сроки поверки. Ниже — таблица расхода ресурсов; годы переключаются нижними вкладками. Нажатие на ячейку открывает нужную запись или ввод показаний на выбранную дату.
- Дашборд, фильтры по году, месяцу и квартире, финансовые графики и графики потребления.
- Договоры и история условий, начисления, частичная оплата, авансы, распределение платежа по месяцам, залоги отдельно от дохода.
- Показания воды, газа и электричества, проверка последовательности, замена прибора, сроки поверки.
- Расходы по квартирам, статус и фактическая дата оплаты, отдельный бюджет собственного жилья, возмещения и оценка по тарифам.
- Годовой результат по фактическим платежам, подробный состав показателей, план и прогноз отдельно.
- Проверяемый импорт исходного годового Excel и CSV, экспорт Excel/CSV, полная JSON-копия и восстановление.
- Серверное хранение в Cloudflare D1, защита от перезаписи при одновременном редактировании.

## Запуск и проверки

Node.js 22.13+ (для тестов с `node:sqlite` рекомендуется Node.js 24).

```sh
npm ci
npm run build
npm test
```

Данные находятся в D1, в таблице `portfolio`: версия схемы и логические коллекции квартир, договоров, приборов и операций сохраняются одной транзакционной записью с оптимистической блокировкой. Для небольшого семейного портфеля это сохраняет целостность взаимосвязанных изменений. При дальнейшем расширении коллекции можно вынести в отдельные таблицы.

Изменения схемы: `npm run db:generate`. Миграции в `drizzle/` применяются хостингом при публикации; приложение не создаёт таблицы при обработке запросов.

`npm run build` создаёт Worker ES module в `dist/server/index.js` с включёнными ресурсами интерфейса. Публикация — через Sites по `.openai/hosting.json` с привязкой D1 `DB`.

## Приватность и конфигурация

Приложение размещается только в **owner-private Sites**. Платформа выполняет вход и защищает HTML и API. API использует одну общую семейную область данных внутри этой границы доступа. **Не публикуйте Worker напрямую в публичном доступе** без добавления серверной проверки аутентификации и членства.

Серверные переменные:

- `PRIVATE_SITE=true` — подтверждение конфигурации приватного хостинга; сама переменная не заменяет платформенную аутентификацию.
- `INITIAL_CONFIG` — необязательный серверный JSON с адресами и датами поверки. Настраивается приватно на хостинге, в Git не хранится. Применяется один раз при создании базы.

Репозиторий содержит только универсальные настройки трёх квартир и согласованные стартовые ставки 50 000 и 35 000 ₽. Адреса, арендаторы, операции и резервные копии в исходный код не включаются.

## Правила расчётов

Прибыль от аренды = полученная аренда + возмещения − оплаченные собственником расходы сдаваемых квартир. Учитываются фактические даты денег, до текущего дня включительно. Залоги, будущие операции и собственное жильё исключаются. Расходы собственного жилья показаны отдельно. Налог учитывается как введённый расход, автоматически не начисляется.

Показания 1 февраля минус показания 1 января дают январский расход. Незаполненные значения не превращаются в ноль. Нестандартный или многомесячный интервал показан отдельно, без выдуманного распределения по месяцам.

Начало учёта по умолчанию — первый день текущего месяца. До переноса всей истории нельзя считать рассчитанную задолженность достоверной за прошлые периоды. Отсутствие денег в истории не устанавливает простой квартиры.

Импорт старого Excel требует проверки. Денежные записи не выбраны по умолчанию. Если точный день получения неизвестен, сохраняется точность «только месяц»; в интерфейсе и Excel показывается месяц, а первое число хранится как техническая дата для расчётов. Кумулятивная аренда 2022 года автоматически не переносится. Архивные поступления не устанавливают договорные начисления: неизвестные обязательства отмечены отдельно, долги и авансы по ним не выдумываются. После ручного подтверждения начисления долг рассчитывается обычным образом. Полное восстановление приложения выполняется JSON-копией; Excel/CSV — аналитические выгрузки.

## Дальнейшее развитие

Внешние push/email-уведомления, автоматическое формирование регулярных расходов и применение залога в счёт долга пока не реализованы. Смена назначения квартиры с историей аренды заблокирована до добавления периодов использования, чтобы не искажать прошлые отчёты. Семейный доступ для второго пользователя настраивается отдельно на хостинге.

Проверки: финансовые сценарии, интервалы показаний, импорт/экспорт, API и конкурентные сохранения, а также интеграционные проверки форм в JSDOM. Проверка в настоящем браузере требует доступной инфраструктуры Sites preview.
